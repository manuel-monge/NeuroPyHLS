# Contributing to NeuroPyHLS

Thank you for helping. This guide covers setup, workflow, tests and the project's rules.

## Setup

```bash
git clone https://github.com/openic-org/NeuroPyHLS.git && cd NeuroPyHLS
uv sync                       # package + dev tools in .venv
uv run pre-commit install     # run the linters on every commit
uv sync --group docs          # only if you work on the docs site
uv sync --group rtl           # only if you write cocotb testbenches
```

The hardware steps also need [Bambu](https://panda.dei.polimi.it/) and [Verilator](https://www.veripool.org/verilator/) on your `PATH`. For hardware files you need [clang-format](https://clang.llvm.org/docs/ClangFormat.html) and [Verible](https://github.com/chipsalliance/verible); without them, those pre-commit hooks are skipped.

## Workflow

1. Open or pick an **issue**, and give it a label.
2. Create a **branch** from `main`, named `feat/<topic>`, `fix/<topic>`, `docs/<topic>`, `chore/<topic>` or `test/<topic>`.
3. Write commit messages as **[Conventional Commits](https://www.conventionalcommits.org/)**, for example `feat(passes): add fixed-point range analysis`.
4. Open a **pull request** to `main`. CI must pass. Once the project has several contributors, a review from a maintainer is required.
5. `main` is protected: nobody pushes to it directly.

## Tests

Tests are marked by the folder they live in:

| Folder | Marker | Needs | Run with |
|---|---|---|---|
| `tests/unit/` | `unit` | nothing | `uv run pytest -m unit` |
| `tests/bambu/` | `bambu` | Bambu + Verilator | `uv run pytest -m bambu` |
| `tests/vitis/` | `vitis` | Vitis HLS | `uv run pytest -m vitis` |

Add `@pytest.mark.slow` to long tests. A tool test is skipped when its tool is not installed.

CI runs only what a change needs. Changes to Python run lint, type checks and unit tests on Python 3.11 and 3.13. Changes to the backends, `rtl/` or `tests/bambu/` also run the Bambu end-to-end tests. Changes to the docs build the site.

**Golden vectors** (`tests/golden/<kernel>/`) are small `.npy`/`.npz` files generated by the Python reference. Commit them, together with a note on how they were made.

## Code style

- Python: ruff (line length 100) and mypy in strict mode on `src/`. Type-annotate public functions.
- HLS C++: clang-format (`.clang-format`).
- Verilog: Verible lint and format.
- Notebooks are stored as Jupytext percent-format `.py` files; `.ipynb` files are git-ignored. Run `uv run jupytext --sync notebooks/*.py` to pair them.

## Data

- Never commit recordings. Add them to `examples/datasets.toml` with a URL and SHA-256; `neuropyhls fetch` downloads them into `data/`.
- Reference repositories go in `examples/sources.toml` with a pinned commit. Don't add submodules.
- Generated outputs are git-ignored, except the small JSON/CSV summaries that feed the docs.

## Licensing

- By contributing, you agree that your contribution is licensed under the repository's licences: Apache-2.0 for code, CC-BY-4.0 for `docs/`. There is no CLA.
- Port only from permissively licensed code, keep the original notice, and add the source to `THIRD_PARTY.md`.
- Never copy GPL or other copyleft code. See "Licensing" in the README.

## AI assistance

AI tools are allowed, under the rules in [AI_CONTRIBUTIONS.md](AI_CONTRIBUTIONS.md):
- disclose their use with a `Co-Authored-By:` trailer and a sentence in the PR description;
- review and understand everything you submit;
- follow your institution's policy for assessed work.

## Releases

The project uses [Semantic Versioning](https://semver.org/). `0.1.0` is tagged at the end of the first CAP26 project. Until 1.0, minor versions may break interfaces.

## Maintainer setup on GitHub (one-off)

These settings are made in the GitHub web interface by an org or repo admin.

1. **Pages:** Settings → Pages → Source: *GitHub Actions*.
2. **Branch protection** for `main` (Settings → Rules → Rulesets):
   - require a pull request;
   - require status checks `ci-ok` (from `ci.yml`);
   - block force pushes;
   - add "1 approving review" once there are several contributors.
3. **Teams** in the `openic-org` organisation:
   - *NeuroPyHLS Maintainers*: Admin;
   - *NeuroPyHLS Investigators*: Maintain;
   - *NeuroPyHLS Students*: Write.
4. **Labels:**
   - `type:` bug, feature, docs, chore, research;
   - `area:` frontend, ir, passes, backend-bambu, backend-vitis, verify, rtl, docs, code-db, lit-db, ci.
5. **Milestones:** see the CAP26 timeline.
